# Henge fork scan, 2026-11-13

Upstream path: `docs/research/fork-scan-2026-11-13.md`. Updated 2026-11-14.

This is a scan of the forks of Leviidev/Henge for changes that upstream does not have yet. Items are ranked against upstream main (`e98920c`, unchanged between the scan and this update). Where an open upstream PR now carries the same change, the item says so. The scan did not build or run anything unless an item says otherwise. All forks involved are GPL-2.0, like upstream, so cherry-picks that keep authorship are allowed. No AGPL or unlicensed code turned up.

## Totals (as of 2026-11-13)

- 179 forks (175 direct, 4 forks of forks); 8 were new since the previous survey on 2026-11-12.
- 162 forks had no push since that survey and were counted as covered.
- 87 branches were compared; 71 branches in 14 forks were ahead of upstream. Of those, 44 had nothing newer than the cutoff, 7 were upstream PR branches, 15 were not ahead, and one (`Tomba247/Henge` branch `source`) shares no history with upstream.
- 20 branches in 10 forks were candidates, with 84 new commits. After dropping merge commits, copies of PR #134 and a zh-CN sync, 63 commits went to review. The review produced 67 entries, 20 marked as candidates.

No item below is merged, so none was dropped as merged. Items that are open PRs are kept and marked, so reviewers can see where the idea came from and who else found it.

## Ranked findings

Each item gives the fork author, the fork commit, what upstream main lacks, and where it stands. Commit links go to the authors' forks.

### 1. Release the high address holds before sizing a Mac's guest RAM (memory, install)
`Tomba247` [18ea2e05](https://github.com/Tomba247/Henge/commit/18ea2e05f67ea96b1e1bfef8d32fa9c38c15534f).
Upstream's JIT prewarm holds about 60 GB of address space (40 + 16 + 4 GB at 0x7000000000, 0x7c00000000 and 0x7b00000000) for Mac apps' allocators, and lets it go only when QEMU starts. `GuestMemory.prepare` measures the largest free mapping before that, so it sees roughly 2.5 GB, the gap left after the JIT region's writable view. Guest RAM is then capped near that figure, and on a phone the install can fail with a misleading storage message.
- **Open upstream PRs:** [#121](https://github.com/Leviidev/Henge/pull/121) (`liukaixiang817`; also releases before install and boot, keeps a failed release for retry, has tests) and [#169](https://github.com/Leviidev/Henge/pull/169) (`eltomato89`; the smaller change). They edit the same three files, so one of them should land. PR #171 was a third version and is closed in favor of #121.
- **Evidence the cap binds:** `eltomato89` logged `guest RAM 2048 MB (asked 8192 ... largest mapping 2560)` on an iPad. On an iPhone Duo with iOS 27.3, two macOS 27.2 installs failed with the holds in place; with #121 the largest mapping went from 2.5 GB to 16.9 GB and the install finished ([comment on #121](https://github.com/Leviidev/Henge/pull/121)). See `jit-setup-notes.md`.
- Drop the rest of Tomba247's commit, which also withdraws a 2 GB code-cache option.

### 2. Edge swipes go to the Mac first (iPhone Duo, input)
`pgabove` [9c7fd1a5](https://github.com/pgabove/Henge/commit/9c7fd1a5d88e4915f5aaa7f6311172706535063a), one line: `.defersSystemGestures(on: .all)` on `SessionView`, next to `.persistentSystemOverlays(.hidden)`. A first swipe from an edge reaches macOS (Dock, menu bar); a second swipe still opens iOS's.
- **Open upstream PR:** [#191](https://github.com/Leviidev/Henge/pull/191) carries the same modifier (from the closed #180). Upstream main has none.
- Not confirmed on a device: that the second swipe reaches iOS. It applies to every session, not only a touchscreen one.

### 3. HV_SYNC_WAIT on by default on iPhone (speed)
`Tomba247` [104522b2](https://github.com/Tomba247/Henge/commit/104522b24b1955e6b89408347e21707503e11c5c). Turns on the existing `HV_SYNC_WAIT` knob (a CPU waiting for another's TLB acknowledgement sleeps after a short spin) for every session, with a Settings switch to turn it off.
- **No open PR.** The knob exists in `core/machine.c`; `EngineTuning` does not set it.
- No measurement in the fork. One iPhone Duo log shows TLBI-acknowledgement waits rising from about 2.6% of time to about 26% once the phone was thermally Hot, which is the case the knob targets. It needs an A/B before it becomes a default. Drop the commit's microphone-log hunk.

### 4. Spin briefly before sleeping on the translation lock (speed)
`mohamedt1996` [e886dd6f](https://github.com/mohamedt1996/Henge/commit/e886dd6f20b76f50b74a9b1c2cead0c55387482b). Most of the commit is a per-page exit list that upstream already has (`7131022`). What is new is a spin of up to 256 `yield`s, with a `trylock` every eighth, before `pthread_mutex_lock(&m->tr_mu)` in `lookup()`. The author reports 2,000 to 4,000 waits a second of 6 to 12 µs on a tablet.
- **Open upstream PR:** [#186](https://github.com/Leviidev/Henge/pull/186) adds a brief yield spin in a `tr_lock()` helper. Upstream main goes straight from `trylock` to `lock`.
- Upstream's stats already count `tr_waits` and `tr_wait_ticks`, so a device A/B can measure it. The "refuse a chain when the list is full" guard does not apply to upstream's per-slot list.

### 5. Free the old pointer image after the swap (stability)
`lunarduststudiodev-rgb` [0291343](https://github.com/lunarduststudiodev-rgb/Henge/commit/0291343263b2c6d91da439e036c72fd0ecf22088). `cursorGlyph` frees the old buffer before it takes `screen_lock`, and the software-frame `drawCursor` reads the buffer without the lock.
- **Open upstream PR:** [#173](https://github.com/Leviidev/Henge/pull/173) swaps under the lock, frees outside it, and takes the lock in every reader. The fork's change narrows the window but does not close it, because the reader stays unlocked.

### 6. Mac-only 24-bit depth/stencil formats (GPU correctness)
`lunarduststudiodev-rgb` [c933ffe1](https://github.com/lunarduststudiodev-rgb/Henge/commit/c933ffe14c64a5dda29097a13cad731c7960e8b5) and [e855504e](https://github.com/lunarduststudiodev-rgb/Henge/commit/e855504e37011f353e1126911893dd5ef9119128). Maps `Depth24Unorm_Stencil8` (255) to `Depth32Float_Stencil8` and `X24_Stencil8` (262) to `X32_Stencil8`, which iOS Metal lacks. The author says this fixes magenta output in Chromium/ANGLE apps; that is unverified.
- **No open PR.** Upstream main has no mapping for 255 or 262.
- The fork's code sits on files upstream does not have, so this is a port, not a cherry-pick. Before porting, capture a GPU trace (`HV_PVG_TRACE_FILE`) of a Chromium app showing the two formats being refused.

### 7. Smaller items
- Drawable retry from 100 ms to 16 ms, 1 MiB NAT socket buffers, and net dequeue batched to 32 frames per lock (`lunarduststudiodev-rgb`, e855504e): **open as [#176](https://github.com/Leviidev/Henge/pull/176)**. No throughput or latency numbers yet. The fork's batching on the virtio RX path adds a second caller to a queue that assumes one, so do not take that part as written.
- Texture-mapper queue at user-interactive QoS (same commit): no PR, not measured.
- Building `tl-samples.dmg` with `SDKROOT` unset (`skarakose` 533fcf1c, `Tomba247` 088aa322): **open as [#168](https://github.com/Leviidev/Henge/pull/168)** (`eltomato89`), which fixes the same Xcode pre-build failure. Upstream's `tl-samples.dmg` rule runs `make -C tl` without unsetting it.

## Skipped after checking

- `pgabove` USB touchscreen on xHCI port 3: no PR. Upstream main has two ports, so port 3 is free there, but [#191](https://github.com/Leviidev/Henge/pull/191) puts its USB mouse on port 3, and [#90](https://github.com/Leviidev/Henge/pull/90) and [#123](https://github.com/Leviidev/Henge/pull/123) already add absolute pointers. The change is about 470 lines of xHCI; retest keyboard and trackpad input if anyone takes it.
- `lunarduststudiodev-rgb` same-block backward branches as direct jumps: no test or measurement, and it turns `HV_SUPERBLOCKS` on with a broken off switch.
- `lunarduststudiodev-rgb` scroll constants (`topSpeed`, `scrollScale`): taste tuning that overlaps [#98](https://github.com/Leviidev/Henge/pull/98) and [#167](https://github.com/Leviidev/Henge/pull/167).
- `lunarduststudiodev-rgb` e855504e also deletes the thermal present throttle. Do not take that.
- The virtio RX double-poll, the connection hash without tombstones, and the glide-watcher change that drops its `glide &&` check are correctness risks.
- Out of scope for this project's priorities: `mohamedt1996` and `muns5965` Android work, `lingbing09` Apple Pencil on iPad, `wicv81-sketch` Lintel (Windows board), `tommyevansx22` Kali ISO, `HamizDev` zh-CN sync, Codemagic CI, and Tomba247's 2 GB code cache (withdrawn by its author).

## Method

1. **List and compare** (`fork-scan-step1.py`, next to this file). It reads `gh api repos/Leviidev/Henge/forks` and the forks of each fork. For every fork pushed after the cutoff it compares the default branch, and any branch with a commit after `BR_CUT`, against upstream main with `compare/main...owner:repo:branch`. A branch is a candidate when it is ahead, is not the head of an upstream PR, and has commits dated after the cutoff that are not PR heads. It writes `forks.json`, `pr_heads.json`, `compare-results.json`, `candidates.json`, `errors.json` and a patch bundle per candidate branch (per-file patches cut at 1,500 lines). Rate-limit errors back off and retry.
2. **Review.** Each bundle went to a model-assisted first pass under a written brief. Priorities: speed toward a laptop-class target, display corners and safe area on an iPhone with an external display, mouse and input, JIT setup, stability. It skipped localization, CI and IPA scripts, rebrands, older-iOS backports, Android, Windows and Linux guests, log-only diagnostics, and non-macOS guests. Each claim had to quote diff lines, and changes that depend on other fork-only commits were marked not self-contained.
3. **Check.** The top picks were read against their patches and against upstream main's source. The status lines above were refreshed on 2026-11-14 with `gh pr list -R Leviidev/Henge --state all`.

To rerun: in an empty directory, edit `CUT` and `BR_CUT` in the script to the time of your last scan, then run `EXCLUDE=yourname/Henge python3 fork-scan-step1.py`. I have only syntax-checked the copy that ships here; the version it came from ran on 2026-11-13. Expect a few hundred API calls.

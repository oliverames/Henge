## Known bugs found, not yet fixed
- `ios/Henge/SessionView.swift:755`: `UIScreen.screens.count > 1` is always true on the iPhone Duo (two integrated panels), forcing `HV_PVG_EXTERNAL="1"` so the built-in inner panel is reported as external (no rounded corners, clipped menu bar/edges). Restrict docked detection to a real external-display scene (`.windowExternalDisplayNonInteractive`) / real external screen rather than `UIScreen.screens.count > 1`.
- `devices/pvg_lite.c:276, 327, 873`: `(size >> 32) >= 2560` and `(cur >> 32) >= 2560` force `p->external = 1` / `ext = 1`, which also catches the Duo's `2848x2000` Retina mode (now active on `main` via `c3a218c`). Drop the `>= 2560` width heuristic and honor `HV_PVG_EXTERNAL=0`.
- **Corner layout constraint (`docs/display-corners.md`, `docs/duo/corner-radius-readers.md`)**: Disassembly of macOS 27.3 WindowServer/CoreUI/AppKit indicates no guest device-tree property pushes menu bar items away from the Duo's ~59 pt corner radius (`SLSMenuBarPrivacyIndicatorInset` caps at 12 pt and is hardware-gated). **Oliver's explicit constraint**: black bars or bands are **not** an acceptable substitute to make corners fit correctly.
- **Stale defaults on Chickadee**: `henge.perf.superblocks` and `henge.perf.wfiSpin` are set true in UserDefaults on Chickadee and turn on `HV_SUPERBLOCKS=1` and `HV_WFI_SPIN=50`. Clear them before benchmarking.

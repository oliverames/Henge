# Henge status, 2026-11-13 (end of session)

Fork `main` is at the commit that adds this file, on top of `4c33b00` (PVG display bring-up fix). Only the primary checkout exists. Device: iPhone Duo "Chickadee", no external display attached this session.

## Done and verified on the Duo
- AppleParavirtDisplay bring-up fix in `devices/pvg_lite.c` (`4c33b00`): vblank no longer raises the unplug bit, connect event is 4, the origin sentinel at +0x4c is kept, and the bogus write at +0x68 is gone. macOS reaches the desktop quickly again (display ack at 11.3 s, 120 GPU frames per 10 s).
- O(segment) code-cache eviction (upstream PR #145): 33 evictions averaged 250 ms, under the 540 ms bar in fork issue #21.

## Known bugs found, not yet fixed
- `ios/Henge/SessionView.swift` (~line 710): `UIScreen.screens.count > 1` is always true on the Duo (two integrated panels), so `HV_PVG_EXTERNAL=1` is set and the built-in panel is marked external (no rounded corners, cut-off content). Use only a real external-display scene.
- `devices/pvg_lite.c` (~lines 271, 321, 873): `width >= 2560` forces `external = true`, which also hits the Duo's 2848x2000 Retina mode. Remove the heuristic and honor `HV_PVG_EXTERNAL=0`.
- Duo Retina (`duo-retina` 956299b, `pr-108` 6d17b5a) is not merged, so the Duo runs 1920x1352 at 1x.
- Stale defaults on Chickadee: `henge.perf.superblocks` and `henge.perf.wfiSpin` are true and turn on `HV_SUPERBLOCKS=1` and `HV_WFI_SPIN=50`. Clear them before any benchmark.
- Oliver's constraint: no black bars or bands as a corner workaround.
